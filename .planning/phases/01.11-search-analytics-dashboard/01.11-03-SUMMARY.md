# Phase 1.11 Plan 03: Read services + aggregate landing dashboard — Summary

Read-side over `search_events` and the admin landing page it powers. Four GDS stat tiles + top-N tables + an empty-state guard, gated by the `search-analytics` section grant so anonymous requests redirect to sign-in, editor-only users see a 404, and admins land on the dashboard.

## What shipped

**Query service (Task 1).** `ISearchAnalyticsQueryService` in `Application/Analytics/` with five methods: `GetSummaryAsync` (4-tile numbers in one server-side scan), `GetTopQueriesAsync` (top-N normalised queries ordered by count DESC), `GetTopZeroResultQueriesAsync` (same shape filtered to `zero_results = true`), `GetRowCountAsync` (cheap empty-state guard), and `GetLatestSearchForSessionAsync` (feedback-form pre-fill helper). Concrete implementation in `Persistence/Analytics/SearchAnalyticsQueryService.cs` — raw Npgsql for the three aggregates, EF LINQ for the row-count and the session-pre-fill. Scoped-registered in `DependencyManager` alongside the existing sink + message-service lines.

**Aggregate SQL (Task 1).** The summary read is one query, one scan:

```sql
SELECT
    COUNT(*)::int AS total_count,
    COUNT(DISTINCT session_id)::int AS unique_sessions,
    COUNT(*) FILTER (WHERE zero_results)::int AS zero_count,
    COALESCE(percentile_cont(0.95) WITHIN GROUP (ORDER BY latency_ms), 0) AS p95_latency
FROM search_events
WHERE occurred_at_utc >= @from AND occurred_at_utc < @to;
```

The top-queries read groups by the normalised value, orders by count DESC (with a stable secondary sort on the query text so ties are deterministic across runs), and limits server-side:

```sql
SELECT
    query_normalised,
    COUNT(*)::int AS c,
    SUM(CASE WHEN zero_results THEN 1 ELSE 0 END)::int AS z
FROM search_events
WHERE occurred_at_utc >= @from AND occurred_at_utc < @to AND query_normalised IS NOT NULL
GROUP BY query_normalised
ORDER BY c DESC, query_normalised ASC
LIMIT @limit;
```

The top-zero-result read is the same shape with an extra `AND zero_results = true` predicate. All bounds bind as `NpgsqlParameter` values — even though the range fields are server-owned `DateTime`, keeping the parameterisation habit means future changes (CSV export with caller-supplied dates, session-scoped filters) inherit the safe path automatically.

**Controller (Task 2).** `SearchAnalyticsController` at `[Route("admin/Search")]` with `[RequireAdminSection(AdminNavKeys.SearchAnalytics)]` at the class level. Constructor-injects the query service. `Index(range, from, to, ct)` resolves the window through the private `ResolveWindow` helper, runs the empty-state row-count first, and only reads the heavier summary + top-N when the corpus is at or above the 20-row threshold. Returns `View("~/Views/Admin/Search/Index.cshtml", viewModel)` explicitly because the view file sits under the admin grouping folder rather than the default MVC per-controller location.

**`ResolveWindow` narrative.** The helper reads `?range=` first: `"24h"` / `"7d"` / `"30d"` / `"90d"` snap to `(now - preset, now)` outright. `"custom"` with both `?from=` and `?to=` supplied normalises Kind to UTC (matching the ObservabilityController AsUtc convention so an offset-less query string does not throw at the timestamptz bind), then clamps `to <= UtcNow` and `from >= UtcNow - 90d` before returning — a hand-edited `?from=1990-01-01` cannot force a seq-scan of the whole table. If the caller supplies a `from >= to` pair (garbage input), the helper snaps to the 7-day default rather than rendering a zero-width window. Anything unrecognised falls back to the 7-day default. Made `internal static` so the follow-on drill-in actions on the same controller can share one window-resolution rule.

**View (Task 2).** `Views/Admin/Search/Index.cshtml` renders:
- `<h1 class="govuk-heading-xl">Search analytics</h1>` + lead paragraph
- A GET form with an inline `govuk-radios` for the five range presets (24h / 7d / 30d / 90d / custom), two `<input type="date">` fields for the custom-range from/to values, and an `Apply filters` + `Reset to last 7 days` button group
- Below the form, either the empty-state `<div class="govuk-inset-text">` (when `HasData` is false, i.e. fewer than 20 rows in the window) OR the tiles + chart-placeholder + top-N tables region
- Four `<div class="sa-tile">` blocks (Searches / Unique users / Zero-result rate / P95 latency) laid out in a `govuk-grid-row` at `govuk-grid-column-one-quarter` — stacks 2×2 at tablet and 1×4 at mobile per GDS grid defaults
- A `<div class="sa-chart-placeholder">` slot with a hint copy (the volume-chart follow-up replaces this with a partial without touching the surrounding layout)
- Two side-by-side `<table class="govuk-table">` blocks — Top queries + Top zero-result queries — each with a visually-hidden caption for screen readers

## Deviations from Plan

### 1. Added a third integration test class (`SearchAnalyticsIndexViewRenderTests`)

**Rule 2 — added critical scaffolding.** The plan's Task 2 `<behavior>` asked for `SearchAnalyticsAuthTests` + `SearchAnalyticsControllerTests` only, and specified "assert the response HTML contains four `<div class=\"sa-tile\">` blocks". An end-to-end HTTP render of `/admin/Search/` was not achievable inside the `HostBuilder` `TestServer` without wiring the full `_AdminLayout` dependency graph (`IPageNodeService`, `IContentBlockService`, `IAdminAccessPolicy`, `IEnumerable<IAdminNavEntry>`, the DevImpersonation cookie stack) — noise that would triple the auth-test scaffolding and still be exercising the layout, not the search view. Followed the `WikiTemplateRenderTests` pattern in `PageTree/`: render the view standalone via `ICompositeViewEngine.GetView` with `isMainPage:false` so `_ViewStart` and the layout are skipped. Coverage of the tile markup, empty-state markup, chart-placeholder marker, top-N tables, and filter-form is equivalent to what an HTTP-level assertion would give.

### 2. Auth tests cover only the two rejection branches (anon → 302, editor → 404) at HTTP level

**Rule 3 — blocking test-infra issue.** The plan's `<action>` asked for an admin-authenticated 200 case too. Making that pass at HTTP level requires the `_AdminLayout` dependency graph noted in Deviation 1 above. Covered the admin-pass-through path via `SearchAnalyticsControllerTests`: the reflection assertions (`Controller_IsGatedBy_SearchAnalyticsSection`, `Controller_HasClassLevelRoute_AdminSearch`) prove the attribute + route are wired to the class, and calling `Index()` directly against a real query service + `PortalDbContext` proves the request path an admin would traverse. Semantically equivalent to a HostBuilder 200 assertion, without the layout-wiring overhead.

### 3. Fixed a boundary-condition test bug during the GREEN phase (`GetRowCount_CountsOnlyRowsInsideTheWindow`)

**Rule 1 — bug in the test seed.** The initial RED seed used `now.AddMinutes(-i)` for `i in 0..4`, which placed one row at exactly `now`. The window `[now - 1h, now)` excludes rows at the upper bound (SQL uses `< to`), so 4 of 5 rows fell inside instead of 5. Reworded the loop to `for i in 1..5` so every seeded row sits strictly earlier than `now`. The assertion `Assert.Equal(5, count)` was the correct pre-condition — the fix landed with the GREEN commit rather than a separate RED-fix commit because the test wasn't asserting the wrong invariant; the seed was constructed sloppy.

### 4. Committed the view under `Views/Admin/Search/` with an explicit `View("~/…", model)` return

**Rule 3 — MVC convention mismatch.** The default view search convention for `SearchAnalyticsController` resolves to `Views/SearchAnalytics/Index.cshtml`, but the plan (and the existing `Views/Admin/*.cshtml` grouping) wants the file at `Views/Admin/Search/Index.cshtml`. Rather than introduce a custom `IViewLocationExpander` (bigger blast radius — every controller would see the new lookup path) or rename the controller to `SearchController` (name-clash with the public-facing `SearchController`), the controller returns `View("~/Views/Admin/Search/Index.cshtml", viewModel)` explicitly. Trade-off accepted: the path string appears in one file rather than being convention-driven, which is a small tax paid once.

### 5. Wired `services.AddGovUkFrontend()` into `SearchAnalyticsIndexViewRenderTests` test host

**Rule 3 — GDS tag-helper resolution failure.** The view uses `<govuk-radios>` / `<govuk-button>` tag helpers, which need `IComponentGenerator` registered. Mirrored the production `Program.cs` registration line inside the test's `HostBuilder.ConfigureServices`. Same package version, same registration call.
