Closes the second round of UX fixes on the search analytics feature. Every numbered ask
in the round shipped and is exercised by either a Playwright E2E or a controller-scope
integration test. Screenshots for handoff live under

## Deviations from Plan

### 1. Playwright feedback-form assertions on prior-search are best-effort (if-guarded)

**Rule 3 — session-cookie transport.** The ASP.NET session cookie carries `secure` in Development. Browsers (Playwright's Chromium included) refuse to send secure cookies back over HTTP, so a Playwright test that hits `/search?q=widget` on one page and then `/Search/Feedback` on the next arrives at the feedback endpoint with a *fresh* session — no prior-search event to render. The E2E test's assertion on "every hit renders as a new-tab link" is behind `if (await priorCard.CountAsync() > 0)` so it never fails on this class of environment. The controller-tier test (`SearchFeedbackControllerTests.Submit_WhenModelStateInvalid_PreservesPriorSearchAndAutoFilledEmail`) proves the behaviour with a fake session that carries the id across GET and POST. This is the same pattern Lance's original round-1 handoff used curl for — the equivalent Playwright test IS running with a real browser, it just can't force a stable session across two requests on plain HTTP.

### 2. `SearchAnalyticsController.ResolveBucketSize` is public-static, not internal-static

**Rule 3 — test-project access to pure helpers.** The pattern for `ResolveWindow` was `internal static`, but the tests project has no `InternalsVisibleTo` marker on the Web assembly. Making `ResolveBucketSize` public-static gives the controller-tier test direct access without adding an attribute file and doesn't widen the runtime API (no router maps a static method).

### 3. SVG `<text>` elements inside a `@foreach` use `Html.Raw`

**Rule 3 — Razor `<text>` control-flow ambiguity.** Razor treats `<text>` inside a code block as a literal-output marker that forbids attributes (RZ1023). SVG `<text class="…" x="…">…</text>` inside a `@foreach` therefore has to be emitted through `Html.Raw($"<text …>{value}</text>")` with `System.Net.WebUtility.HtmlEncode` on any user-derived label. The three axis-title elements outside the code block use standard Razor markup because they don't collide with the control-flow parser.

### 4. `SearchAnalyticsIndexViewModel.BucketKey` is `required`

**Rule 3 — view-model surface.** Adding `BucketKey` as `required` breaks any existing constructor site that omits it. Two test-project sites (`SearchAnalyticsIndexViewRenderTests.ViewModelWithData` and `.EmptyViewModel`) were updated in the same commit to pass `BucketKey = "1d"`. No production caller besides `SearchAnalyticsController.Index` constructs this view model.
