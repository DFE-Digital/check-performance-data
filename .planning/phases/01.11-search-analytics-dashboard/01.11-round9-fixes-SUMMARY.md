The seed is a one-shot, low-frequency, admin-triggered action — a hosted-service worker would need a queue channel + a shutdown hook + retry semantics for a job type that expects to run exactly once per click and never resume across process restarts. Task.Run + IServiceScopeFactory delivers the fire-and-forget shape in ~40 lines; the job store is deliberately in-memory so a container restart drops mid-flight jobs (that's fine — the seeded rows that already landed are persistent through the sink, and the admin can click again)."
  - "Singleton in-memory store, NOT persisted to Postgres. The store's only consumer is the client-side poller between a POST and completion — a job that survives a process restart adds no user value. The tests are simpler, DB migrations aren't needed, and there is no state to reconcile after a crash. The 5-minute retention window is long enough for a normal reload to observe the completed state."

## Deviations from Plan

### 1. Round-8 `SubmitLast24Hours_BannerAppearsAndDashboardHasData` test rewritten

**Rule 1 — bug caused by my change.** The round-8 test asserted the presence of
the TempData success banner after a form submit. My JS layer intercepts the
submit + POSTs via fetch, so the browser never navigates to the redirect and the
banner never renders (fetch consumes the 302). Rewrote the assertion to expect
the modal completion state — same intent (the seed happened, the user sees
confirmation, the dashboard link is present) but the surface changed. The banner
path is still valid for JS-disabled users and still renders via TempData on the
GET after the redirect.

### 2. Kept batch size at 200 (deferred R6 throughput tune)

**Rule 3 — scope boundary.** R6 was flagged as SECONDARY and bounded. Bumping
the batch size directly reduces the progress-tick cadence, and the primary UX
win from this round is the modal — a Quarter seed will still emit ~125 ticks at
batch 200, which is more than the 500 ms poller can render in 60 s of runtime.
Left at 200. If a dedicated throughput round wants to hit sub-30-second seeds
for 25k events, it should look at bulk-COPY inserts through `NpgsqlBinaryImporter`
rather than tuning the sink batch size.

### 3. Cancelled-modal screenshot skipped

**Rule 3 — race window.** The Cancel test kicks a Quarter (25 000-event) seed
and clicks Cancel after 400 ms of runtime. On this WSL2 Docker host the seed
often completes before the DELETE handler runs and the modal transitions
straight to Completed. The test tolerates either outcome (cancelled OR completed)
and only saves the screenshot when it observes the cancelled panel. Cancel
wiring is verified independently by the integration test
`SeedAsync_HonoursCancellationBetweenBatches` (cancels via the token; asserts
< 5000 rows land) and by the DELETE endpoint being wired + hit in the E2E test.

### 4. Docker container OIDC config env var was missing on this worktree

**Rule 3 — build correctness.** The `DFESIGNIN_CLIENTID` env var was empty in
this WSL shell (not set at the shell level, and `docker-compose.yaml` uses
`${DFESIGNIN_CLIENTID}` as the interpolation), which caused `OpenIdConnectOptions.Validate()`
to throw 500 on every request. Restarted the web container with
`DFESIGNIN_CLIENTID=stub-dev-id docker compose up -d web` to unblock the E2E
run — pre-existing environmental issue in this worktree, not caused by round-9
changes. Unit + integration tests are unaffected (no OIDC dependency).
