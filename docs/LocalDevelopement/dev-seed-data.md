# Dev seed data

What the dev seeders create, and in what order. Dev seeders are data: they have no tests and carry `[ExcludeFromCodeCoverage]` (see `AGENTS.md`).

`DevDataSeeder` runs on startup in dev (and when `SeedDevelopmentData=true`). Seeding order:
1. `SeedCountries` — populates the `Countries` table from the embedded FCDO CSV (`Persistence/Seeding/Data/FCDO_Geographical_Names_Index.csv`, Latin-1 encoded) plus hand-written UK home nations and Crown Dependencies. Always runs first; uses `ExecuteDeleteAsync` for idempotency.
2. `SeedCheckingWindows` — inserts checking window rows into PostgreSQL: one KS4 June fixture window, "Key Stage 4 June" (ingested by `SeedExerciseFixtures`; its exercise's `VisibleUntil` is a month after its end date, so it stays on the landing page read only) four 16-19 windows, one per step of the results enquiry year, "Key Stage 4 Autumn" (`PlaceholderWindow` plus an enabled pupil data exercise with one `pupils` slot, a results enquiry and a "Summary" data share; see below) and "Key Stage 2" (`PlaceholderWindow`: the wizard's default exercises, then the slots below). **Kingsmead (860/4070), the school the dev impersonation signs in as, has data in every window**, KS2 included (`SeedKs2Summary.Schools`), so a developer can walk every journey. "Key Stage 2" also has an enabled "Summary" data share (no kind, display only, tab "Summary", layout `Vertical`, one slot `summary`), filled by `SeedKs2Summary` from a generated December-shaped file with `Web/Data/Ingress/ks2/summary_schema.json` and validated, so schools see that window with only its Summary tab. The schema serves both supplier files (`x-csv.columns` `september` / `december`); the four disadvantaged pupil fields are December only. **"Key Stage 4 Autumn"** (`SeedKs4AutumnSamples`) has three enabled exercises, each validated once, so each has one release. Pupil data checking (tab "Pupils", layout `InclusionTabs`) has the KS4 pupils from `SeedPupilData.Ks4Pupils` in the supplier's autumn shape with `Web/Data/Ingress/ks4autumn/pupils_schema.json`. The results enquiry (tab "Results", late results warning on) has a slot for every KS4 file: `KS4_MAIN` is filled with `results_schema.json` and `KS4_LR1` with `results-late_schema.json`; `KS4_LR2` and `KS4_Revised` are empty. Only Kingsmead has results: English and maths for every third included pupil and every fifth non-included one. Alice Smith also has an early maths entry (S2024) and a late results 1 amendment; Bob Smith has only a late result. The "Summary" data share (tab "Summary", layout `Vertical`, one slot `summary`) has one row per school with `summary_schema.json`, worked out from the school's included pupils. Progress 8 and prior attainment fields are blank, because the specification sets them to null in 2025 and 2026. Abingdon School is independent, so only the independent report's fields have values. The sample files also go to the ingress storage account, container `ks4-autumn`. `SeedCheckingWindows` gives them only slots; the Web seed fills them, each seed doing the step before it and then its own, validating each time (so each step makes a release). **"16 to 19 Oct"** (`SeedPost16OctoberSamples`): the two student files, the previously published file (a third pupil-data slot, `FeedsJourney` false, in every 16-19 window) and included, non-included and late results 1 validated; late results 2 is still awaited. **"16 to 19 Nov"** (`SeedPost16NovemberSamples`): + late results 2, and pupil data's "Value Added" slot filled (`students-value-added_schema.json`) and validated. **Every 16-19 window's pupil data** has three value added slots (`FeedsJourney` false, empty and not required until their step), each replacing the one before (`SeedPost16ValueAdded`): "Value Added" (Nov), "Value Added: revised" (Feb) and "Value Added: revised incl. retention" (Mar). **"16 to 19 Feb"** (`SeedPost16FebruarySamples`): + included revised and non-included revised, with included, non-included and both late files retired, and the previously published revised pupil-data slot (in every 16-19 window, `FeedsJourney` false, empty and not required until February) filled with `students-previously-published-revised_schema.json`, made required, previously published retired, and pupil data validated as a second release. **"16 to 19 Mar"** (`SeedPost16MarchSamples`): + included revised with retention (`results-included-revised-retention_schema.json`), with included revised retired. Its pupil data also has an "Aims" slot (`FeedsJourney` false, empty and not required until March) filled from `students/aims.csv` with `students-aims_schema.json` and validated with March's value added. **Every 16-19 window** also has a "Summary" data share (no kind, display only, tab "Summary", the first tab, layout `Vertical`) with four slots, one per step, each replacing the one before (`SeedPost16Summary`): "Summary" (Oct, `summary-autumn_schema.json`), "Summary with value added" (Nov, `summary-november-va_schema.json`), "Summary with value added: revised" (Feb, `summary-november-va-revised_schema.json`, the November columns), "Summary with value added: revised incl. retention" (Mar, `summary-retention_schema.json`; a slot name is at most 50 characters). Each step's schema has its own section (the heading schools see), collection and download file. **Every 16-19 window** also has a "Student campus" data share (no kind, display only, tab "Campus", one slot `campus`), filled in the October step (`SeedPost16PupilCampus`) from `students/campus.csv` with `students-campus_schema.json`; later steps keep that release. `SeedPost16OctoberSamples.AddResultsFilesAsync` is the shared "link, retire, validate" step. Every window's sample CSVs also go to the ingress storage account (containers `16-to-19-oct`, `-nov`, `-feb`, `-mar`), so each window is the "before" state for doing the next step by hand; schemas are in `Web/Data/Ingress/post16/`. See `docs/results-enquiry.md` → Local development; testing guides `docs/testing-late-results-2.md` and `docs/testing-revised-results.md`. There is no 16-19 E2E journey coverage.

Then, separately in Web startup (dev only):
3. `SeedPupilData.ExecuteSeedAsync` (`Web/Seeding/`) — writes per-school pupil JSON (`data/{laestab}_pupils.json` in each `{windowId}` container) via `IPupilDataBlobClient`, 120 included + 120 non-included pupils per school × window (`PupilsPerGroup`). That count is deliberately well past the list's page size of 10 so pagination — including the ellipsis window — is exercised locally; don't shrink it back to a page or two. Generated names pair firstname `n % 20` with surname `(n / 20) % 20` so all 400 combinations are distinct, and the non-included group is generated from an index shifted by `NonIncludedIndexOffset` so the two groups never collide on name, UPN, Cypmd id or match ref. Included index 0 is Alice Smith / `A86040700001B`, which E2E tests and `SeedChangeRequests` depend on. Kingsmead also carries a deliberate same-name and date-of-birth pair, Casey Carter born 15/03/2010, CYPMD `800001` (included) and `800002` (not included), in the KS4 June and KS4 Autumn windows (`SeedPupilData.Ks4PairWindowIds`); the Add duplicate check and the merge E2E tests depend on it (#747 added KS4 Autumn). The checking-window GUIDs come from `DevDataSeeder`'s public constants.
